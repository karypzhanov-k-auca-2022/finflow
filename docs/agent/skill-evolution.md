# Skill evolution

Do not silently rewrite AGENTS.md, docs/agent guidance, or repository-local Skills while solving ordinary development tasks.

A reusable rule may be worth adding when:

- a mistake is likely to recur;
- repository exploration was repeatedly wasteful;
- an important repository convention was missing; or
- verification repeatedly missed an important issue class.

By default, propose the instruction change before editing it. Show:

1. the file that should change;
2. the exact proposed rule; and
3. why the rule is reusable.

Apply it only after explicit approval.

Do not persist Jira-specific details, one-off debugging facts, temporary file paths, or a single implementation choice. Prefer small replacements or clarifications over continually appending instructions. Remove obsolete guidance when an approved update supersedes it.
